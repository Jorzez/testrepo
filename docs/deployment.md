# Запуск и развёртывание

[← README](../README.md)

## Запуск

Работающий стек в интернет не ходит: compose сам не обращается к реестру
образов (`pull_policy: ${PULL_POLICY:-never}`), а vLLM читает веса модели
из локального каталога и работает с `HF_HUB_OFFLINE=1`. Сеть нужна только
при релизе — скачать образы, собрать API и интерфейс (pip и npm) и докачать
веса. Последовательность команд — в [релизе на сервере](release.md).

Настройки берутся из `.env`; шаблон — `.env.example`. Обязательны
`NEO4J_PASSWORD`, `VLLM_MODEL` и настройки входа, полный список — в таблице ниже.

Перезапуск уже установленного стека сети не требует:

```bash
docker compose up -d --no-build
```

`--build` без сети не сработает: пересборка образов — часть релиза.

Для разработки, когда стек может ходить в интернет и во время работы,
есть надстройка `docker-compose.online.yml`: она разрешает докачивать
образы и берёт веса модели с Hugging Face в кэш-том:

```bash
docker compose -f docker-compose.yml -f docker-compose.online.yml up -d --build
```

Порядок подъёма задан через `depends_on`: `neo4j` → `seeder` → `api`;
`vllm` поднимается параллельно (при `VLLM_REPLICAS=0` — не поднимается).
API стартует только после того, как сидер успешно отработал: схема
с ограничениями уникальности (в том числе служебных замков `:CatalogLock`)
должна быть создана до первой правки каталога. Готовности модели API
не ждёт: вход, каталог и настройки работают, пока vLLM грузит веса (несколько минут для 27B-модели, `start_period: 900s`),
а готовность модели видна в `/ready` (поле `llm`). Сидер при каждом подъёме
создаёт схему и загружает данные только в пустой каталог — см. [работу с
данными](data.md).

| Сервис | Адрес | Откуда доступен |
|---|---|---|
| Редактор каталога | http://localhost:3000 | на адресе `WEB_BIND`; нужен вход |
| API | http://localhost:8080 | только с самого сервера; пользователям — через `/api` интерфейса |
| Swagger | http://localhost:8080/docs | только с сервера и при `ENABLE_DOCS=1` |
| Neo4j Browser | http://localhost:7474 | только с сервера |
| Keycloak стенда | http://localhost:8180 | только с сервера; только с профилем `idp` |

Наружу может быть опубликован один порт — интерфейс. Neo4j, vLLM, API
и Keycloak стенда привязаны к `127.0.0.1`: с рабочего места к ним ходят через
SSH-туннель (`ssh -L 7474:localhost:7474 -L 7687:localhost:7687 <сервер>`).
Перед интерфейсом ставится прокси с TLS — см. [доступ и безопасность](security.md#настройка-на-сервере);
там же настройка клиента в Keycloak и `WEB_BIND`.

Логи всех контейнеров ротируются (json-file, `LOG_MAX_SIZE` × `LOG_MAX_FILES`,
по умолчанию 50 МБ × 5); vLLM запускается без `--enable-log-requests` и
промпты в лог не пишет. Журнал аудита API дополнительно пишется в файл на
томе `api_audit` — см. [журнал аудита](security.md#журнал-аудита). При
остановке API идущим запросам даётся 45 секунд доработать
(`--timeout-graceful-shutdown 45`), docker ждёт 60 (`stop_grace_period`).

### Видеокарта

Модель по умолчанию — `Qwen/Qwen3.6-27B-FP8`: веса около 30 ГБ на диске
и в памяти GPU. Рассчитано на одну RTX PRO 6000 (96 ГБ): остаток памяти
уходит под кэш одновременных запросов (`LLM_MAX_CONCURRENCY`). Минимум —
карта на 40 ГБ с поддержкой FP8 (Ada, Hopper, Blackwell), но тогда меньше
запросов идёт параллельно. Для Blackwell нужен vLLM не ниже v0.28;
`VLLM_IMAGE` по умолчанию — v0.30.0.

### Без GPU

Модель на другом сервере — внешний OpenAI-совместимый эндпоинт. Задайте
в `.env` `VLLM_URL` (и `VLLM_API_KEY`, если эндпоинт требует ключ)
и `VLLM_REPLICAS=0` — сервис `vllm` (`deploy.replicas: ${VLLM_REPLICAS:-1}`)
тогда не запускается, в том числе при ручном `docker compose up -d`:

```bash
# .env: VLLM_URL=https://llm.corp.local/v1, VLLM_REPLICAS=0
docker compose up -d
```

При внешнем `VLLM_URL` должно быть `VLLM_REPLICAS=0`, без него —
`VLLM_REPLICAS=1`: иначе compose поднимет vLLM на сервере без GPU или API
пойдёт в выключенный локальный vLLM. Веса модели при релизе тогда не нужны
(шаг 4 [релиза](release.md) пропускается). Вернуться к локальной
модели — убрать `VLLM_URL` и задать `VLLM_REPLICAS=1`.

## Релиз

Установка и обновление на сервере — последовательность docker-команд,
описанная в [docs/release.md](release.md): код из git, образы
(`PULL_POLICY=always docker compose pull`), сборка API и интерфейса
(`docker compose build --pull`), веса модели (`docker compose run --rm model`)
и запуск без сети (`docker compose up -d --no-build`).

Что в работе закрыто от сети и где это задано:

| Обращение в интернет | Когда и чем закрыто |
|---|---|
| `pip install` и `npm ci` | только при сборке образов (`docker compose build`); в контейнерах готовые пакеты и статика |
| `docker pull` образов | только с `PULL_POLICY=always` при релизе; по умолчанию у всех сервисов `pull_policy: never` |
| загрузка весов с Hugging Face | только разовым сервисом `model` (профиль `release`); vLLM — том `${MODELS_DIR}:/models`, `--model /models/…`, `HF_HUB_OFFLINE=1` |
| телеметрия vLLM и Hugging Face | `VLLM_NO_USAGE_STATS=1`, `HF_HUB_DISABLE_TELEMETRY=1`, `DO_NOT_TRACK=1` |

Веб-интерфейс внешних скриптов и шрифтов не подключает: всё собрано
в образ, браузеру пользователя интернет тоже не нужен.

### Зависимости API

`api/requirements.txt` — прямые зависимости, `api/requirements.lock` —
полный список с версиями и sha256, по которому собирается образ
(`--require-hashes --no-deps`: подменённый пакет или пакет сверх lock —
ошибка сборки). После правки `requirements.txt`:

```bash
docker run --rm --platform linux/amd64 -v "$PWD/api:/src:ro" \
  python:3.12-slim@sha256:a6e34c598f2467ed0e9a8d349809fcd8b5c603269512df273a0bb1784edc11b1 sh -ec '
    pip install --quiet --root-user-action=ignore --disable-pip-version-check pip-tools >&2
    cp /src/requirements.txt /src/requirements.lock /tmp/ && cd /tmp
    pip-compile --quiet --generate-hashes --strip-extras --allow-unsafe --no-emit-index-url \
      --output-file requirements.lock requirements.txt >&2
    cat requirements.lock' > api/requirements.lock.new \
  && mv api/requirements.lock.new api/requirements.lock
```

Существующий lock берётся за основу: новые пакеты дописываются, версии
прочих не меняются. Поднять все незакреплённые транзитивные версии —
добавить `--upgrade` к `pip-compile`.

Нужны интернет и Docker. Lock собирается в контейнере с тем же базовым
образом, что и API (`ARG PYTHON_IMAGE` в `api/Dockerfile`), под `linux/amd64` —
маркеры окружения вычисляются как на сервере. Каталог `api` смонтирован
только на чтение, а lock выводится в stdout: файл остаётся за владельцем
на хосте, а при ошибке прежний lock цел. На сервер новый lock попадает
со следующим релизом.
Согласованность lock и `requirements.txt` проверяет тест `tests/test_lock.py`.

## Обновление и обслуживание

**Резервная копия.** Перед обновлением, миграциями, полным сбросом и
`SEED_DATA=1` снимите дамп — команды и восстановление в [работе с данными](data.md#резервная-копия)
(на время дампа и его проверки API и Neo4j останавливаются). Журнал аудита лежит на томе
`api_audit` и в дамп не входит — включите том в резервное копирование
сервера.

**Смена пароля Neo4j.** Пароль записывается в базу при первом старте;
новое значение `NEO4J_PASSWORD` в `.env` его не меняет, и healthcheck
с новым паролем не пройдёт. Сначала меняется пароль в базе, потом `.env`:

```bash
docker compose exec neo4j cypher-shell -u neo4j -p '<старый>' \
  "ALTER CURRENT USER SET PASSWORD FROM '<старый>' TO '<новый>'"
# поправить NEO4J_PASSWORD в .env
docker compose up -d
```

**Кэш оценок SMART.** Ограничение уникальности `:SmartScore.goalHash`
создаёт сам API при первой записи оценки, а не сидер: если в базе от прежних
версий остались повторяющиеся `goalHash`, остаётся обычный индекс,
в логе API — предупреждение. Очистка кэша «Оценки по SMART» в «Настройках»
удаляет все оценки, после этого ограничение создастся.

## Переменные окружения

Переменные, которые читает API, перечислены в `environment` сервиса `api`
в `docker-compose.yml` с теми же значениями по умолчанию, что в коде
(сверяет `tests/test_deploy.py`). Переменная из `.env`, которой там нет,
до контейнера не доходит.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `NEO4J_PASSWORD` | — | пароль Neo4j (обязательна); смена — см. выше |
| `VLLM_MODEL` | `Qwen/Qwen3.6-27B-FP8` | имя, под которым модель доступна через API vLLM (задайте явно) |
| `VLLM_MODEL_DIR` | `Qwen3.6-27B-FP8` | каталог весов внутри `MODELS_DIR` (задайте явно) |
| `MODELS_DIR` | `./models` | каталог с весами моделей на хосте |
| `VLLM_IMAGE` | `vllm/vllm-openai:v0.30.0` | образ vLLM, скачивается при релизе |
| `APP_VERSION` | `latest` | тег образов API и интерфейса; разный у релизов — откат без сети ([release.md](release.md#откат)) |
| `HF_TOKEN` | — | только для сервиса `model` при релизе, если модель закрытая; работающему стеку не нужен |
| `VLLM_URL` | `http://vllm:8000/v1` | адрес OpenAI-совместимого API; внешний — вместе с `VLLM_REPLICAS=0`, см. «Без GPU» |
