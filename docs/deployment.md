# Запуск и развёртывание

[← README](../README.md)

## Запуск

Стек рассчитан на сервер без доступа в интернет: compose никогда не
обращается к реестру образов (`pull_policy: never`), pip при сборке
образа API ставит зависимости из `api/vendor/wheels`, а vLLM читает веса
модели из локального каталога и работает с `HF_HUB_OFFLINE=1`. Поэтому
перед первым запуском нужны загруженные образы и веса — как их получить,
описано в разделе «Развёртывание без интернета».

Настройки берутся из `.env`; шаблон — `.env.example`. Обязательны
`NEO4J_PASSWORD` и `VLLM_MODEL`, полный список — в таблице ниже.

```bash
cp .env.example .env      # и заполнить
docker compose up -d
```

`--build` нужен только если менялся код. Образ API собирается и без
сети, при условии что базовый образ `python:3.12-slim` загружен. Образ
интерфейса без сети не собрать (`npm ci`), поэтому на сервере его не
пересобирают: новый образ готовит `prepare.sh`.

На машине с интернетом (разработка, стенд) добавьте надстройку
`docker-compose.online.yml`: она разрешает докачивать образы и берёт веса
модели с Hugging Face, как раньше. Заранее готовить ничего не нужно:

```bash
docker compose -f docker-compose.yml -f docker-compose.online.yml up -d --build
```

Порядок подъёма задан через `depends_on`: `neo4j` → `seeder` → `api`.
API стартует только после того, как сидер успешно отработал, а vLLM
прошёл healthcheck (загрузка весов 8B-модели занимает несколько минут,
поэтому у неё `start_period: 900s`).

| Сервис | Адрес | Откуда доступен |
|---|---|---|
| Редактор каталога | http://localhost:3000 | снаружи; нужен вход |
| API | http://localhost:8080 | только с самого сервера; пользователям — через `/api` интерфейса |
| Swagger | http://localhost:8080/docs | только с сервера и при `ENABLE_DOCS=1` |
| Neo4j Browser | http://localhost:7474 | только с сервера |

Наружу опубликован один порт — интерфейс. Neo4j, vLLM и API привязаны
к `127.0.0.1`: с рабочего места к ним ходят через SSH-туннель
(`ssh -L 7474:localhost:7474 -L 7687:localhost:7687 <сервер>`). Перед
интерфейсом ставится прокси с TLS — см. [доступ и безопасность](security.md#настройка-на-сервере);
там же настройка входа через LDAP / Active Directory.

Для запуска без GPU укажите внешний OpenAI-совместимый эндпоинт
через `VLLM_URL` и поднимайте стек без сервиса `vllm`.

## Развёртывание без интернета

Набор для переноса собирается на любой машине с Docker и интернетом,
а на сервере ничего не скачивается. Оба шага — скрипты в `scripts/offline/`.

**На машине с интернетом:**

```bash
cp .env.example .env      # VLLM_MODEL, VLLM_IMAGE, при необходимости HF_TOKEN
scripts/offline/prepare.sh
```

Скрипт делает пять вещей:

1. Скачивает wheel-файлы Python под платформу сервера в `api/vendor/wheels`
   (по умолчанию `linux/amd64`, меняется через `TARGET_PLATFORM`). Набор
   небольшой и лежит в git вместе с `MANIFEST.sha256`, поэтому образ API
   собирается одинаково на любой машине.
2. Собирает образ API с `--network none` — сборка проверяется здесь,
   а не впервые на сервере. Собирает образ интерфейса: React-приложение
   собирается в статику и кладётся в nginx.
3. Скачивает образы `neo4j`, `vllm/vllm-openai` и `python:3.12-slim`
   и сохраняет их вместе с образами API и интерфейса в `dist/offline/images.tar`.
4. Скачивает веса модели с Hugging Face в `models/<VLLM_MODEL_DIR>`.
   Каталог `models/` в git не попадает.
5. Упаковывает исходники в `dist/offline/goal-checker-src.tar.gz` и пишет
   `MANIFEST.txt` и контрольные суммы.

На сервер переносятся каталог `dist/offline/` и каталог с весами.

**На сервере без интернета:**

```bash
./install.sh /opt/goal-checker
```

Скрипт распаковывает исходники, загружает образы через `docker load`,
проверяет, что все образы из `images.list` на месте и что рядом лежат веса
(`config.json` в каталоге модели), создаёт `.env` из шаблона, если его нет,
и поднимает стек командой `docker compose up -d --no-build`. Любая
недостача останавливает установку до запуска compose — в том числе
незаполненные настройки входа (`LDAP_URL`, `LDAP_USER_TEMPLATE`,
`AUTH_ADMIN_LOGINS`): стек, в который некому войти, не поднимается.

Что именно закрыто от сети и где это задано:

| Обращение в интернет | Чем заменено |
|---|---|
| `pip install` при сборке API | колёса в `api/vendor/wheels`, `PIP_NO_INDEX=1` в `Dockerfile` |
| `npm ci` при сборке интерфейса | только в `prepare.sh`; на сервер приезжает готовый образ `goal-checker-web` |
| `docker pull` образов | `pull_policy: never` у всех сервисов, образы из `images.tar` |
| загрузка весов с Hugging Face | том `${MODELS_DIR}:/models`, `--model /models/…`, `HF_HUB_OFFLINE=1` |
| телеметрия vLLM и Hugging Face | `VLLM_NO_USAGE_STATS=1`, `HF_HUB_DISABLE_TELEMETRY=1`, `DO_NOT_TRACK=1` |

Веб-интерфейс внешних скриптов и шрифтов не подключает: всё собрано
в образ, браузеру пользователя интернет тоже не нужен.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `NEO4J_PASSWORD` | — | пароль Neo4j (обязательна) |
| `VLLM_MODEL` | — | имя, под которым модель доступна через API vLLM (обязательна) |
| `VLLM_MODEL_DIR` | `Qwen3-8B` | каталог весов внутри `MODELS_DIR` |
| `MODELS_DIR` | `./models` | каталог с весами моделей на хосте |
| `VLLM_IMAGE` | `vllm/vllm-openai:v0.9.2` | образ vLLM, тег должен совпадать с офлайн-набором |
| `APP_VERSION` | `latest` | тег образа API, собранного `prepare.sh` |
| `HF_TOKEN` | — | только для `prepare.sh`, если модель закрытая; на сервере не нужен |
| `VLLM_URL` | `http://vllm:8000/v1` | адрес OpenAI-совместимого API |
| `LLM_TIMEOUT_SECONDS` | `60` | таймаут запроса к модели |
| `LLM_MAX_RETRIES` | `2` | число повторов запроса к модели |
| `BULK_MAX_WORKERS` | `4` | параллельных обращений к модели при пакетной проверке |
| `MAX_GOALS_PER_REQUEST` | `200` | предел размера пакета в `/check-goals` |
| `LOG_LEVEL` | `INFO` | уровень логирования |

Вход и сессии (подробности — в [доступе и безопасности](security.md)):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `AUTH_BACKEND` | `ldap` | где проверять пароль: `ldap` или `static` (только стенд) |
| `LDAP_URL` | — | адрес каталога, `ldaps://…` (обязательна при `ldap`) |
| `LDAP_USER_TEMPLATE` | — | имя для подключения к каталогу, например `{login}@corp.local` (обязательна при `ldap`) |
| `LDAP_CA_FILE` | системные | корневой сертификат домена, путь внутри контейнера (`/certs/…`) |
| `LDAP_STARTTLS` | `0` | `1` — `ldap://` с STARTTLS вместо `ldaps://` |
| `LDAP_TIMEOUT_SECONDS` | `5` | таймаут обращения к каталогу |
| `AUTH_ADMIN_LOGINS` | — | логины, которые всегда администраторы, через запятую |
| `AUTH_STATIC_USERS` | — | `логин:запись` для `AUTH_BACKEND=static`; запись делает `python auth.py hash` |
| `SESSION_IDLE_MINUTES` | `30` | выход после простоя |
| `SESSION_MAX_HOURS` | `12` | предельный срок сессии |
| `SESSION_COOKIE_SECURE` | `1` | `0` — cookie сессии и по HTTP, только для стенда |
| `LOGIN_MAX_ATTEMPTS` | `5` | неудачных входов подряд до блокировки логина |
| `LOGIN_MAX_ATTEMPTS_PER_IP` | `30` | то же для адреса клиента |
| `LOGIN_LOCK_MINUTES` | `15` | окно подсчёта и срок блокировки |
| `TRUSTED_PROXY` | `127.0.0.1` | адрес прокси с TLS, чьему `X-Forwarded-For` верит nginx интерфейса |
| `ENABLE_DOCS` | `0` | `1` — включить Swagger |
