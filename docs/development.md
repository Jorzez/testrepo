## Проверка Cypher

Юнит-тесты подменяют драйвер Neo4j, поэтому текст запроса в них никогда не
разбирается: запрос с ошибкой области видимости проходит весь набор тестов
и падает только у пользователя. Ровно так сломалось удаление узлов —
переменная использовалась в `RETURN` после `WITH`, который её не пронёс.

`api/verify_cypher.py` закрывает этот класс ошибок:

```bash
cd api
python verify_cypher.py             # разбор областей видимости, база не нужна
python verify_cypher.py --explain   # плюс EXPLAIN каждого запроса на живой базе
```

Первый режим собирает все Cypher-строки проекта (константы модулей и литералы
внутри функций) и ищет переменные, использованные вне области видимости.
Он же входит в набор тестов (`tests/test_cypher.py`), поэтому запускается
на каждом прогоне.

Второй режим прогоняет `EXPLAIN` каждого запроса на живой Neo4j: полноценный
разбор и планирование средствами самой СУБД, без выполнения. Это единственный
способ поймать всё, что зависит от версии Neo4j.

## Тесты

```bash
cd api
pip install -r requirements-dev.txt
pytest
```

Тесты не требуют ни Neo4j, ни vLLM — внешние зависимости подменяются.
Покрыты: разбор ответа модели (блоки `<think>`, markdown-ограждения,
мусор), сопоставление имён атрибутов при расхождении написания,
поведение fail-closed, разбиение Cypher-скрипта, идемпотентность и
стабильность выгрузки, диагностика в `/ready`, сборка дерева каталога,
запрет на двойников и на удаление неархивированных узлов — то есть ровно
те места, где расхождение схемы и кода уже приводило к молчаливым отказам.

Качество распознавания эти тесты не проверяют: модель в них подменена.
Его показывает проверка примеров на настоящей модели — раздел «Замечания»,
см. [веб-интерфейс](web-ui.md#проверка-примеров-на-модели).

Вход и права — в `tests/test_auth.py`: каждый маршрут без сессии отвечает
`401` (новый маршрут без проверки прав роняет этот тест), матрица ролей,
одинаковый отказ на любую неудачу входа, блокировка после серии неудач,
срок жизни сессии, немедленное действие смены роли и блокировки, журнал
аудита без паролей, поведение LDAP (пустой пароль, отказ от соединения
без шифрования, недоступный каталог). В остальных тестах HTTP-слоя
пользователь подменяется через `app.dependency_overrides[auth.current_user]`.

## Интерфейс

Редактор каталога — React + TypeScript на Vite, исходники в `web/`.
Нужен Node.js 22.

```bash
cd web
npm install
npm run dev:mock      # http://localhost:5173 с фейковым API — без Neo4j, vLLM и Docker
npm run dev           # то же, но с настоящим API на :8080 (прокси на тот же origin)
```

В фейковом API три учётки — `admin`, `editor`, `viewer`, пароль у всех
`demo` (константа `MOCK_PASSWORD`): так видно интерфейс каждой роли.
С настоящим API входят учёткой стенда из `.env`.

Оба режима перезагружают страницу при каждом сохранении файла. Адрес
настоящего API меняется переменной `VITE_API_TARGET`.

Фейковый API (`web/mock/backend.ts`) держит данные в памяти и повторяет
поведение настоящего, видимое интерфейсу: формы ответов, `401`/`403`/`404`/`409`,
вход и роли, каскадное удаление, защиту от двойников. Данные сбрасываются при
перезапуске. Поменяли ответ API — поправьте фейк и типы в `web/src/api/types.ts`:
у эндпоинтов нет `response_model`, поэтому OpenAPI ответы не описывает
и типы из него не генерируются.

### Проверки интерфейса

```bash
cd web
npm run typecheck                 # TypeScript
npx playwright install chromium   # один раз
npm test                          # e2e на собранной версии
PW_CHANNEL=chrome npm test        # то же на установленном Google Chrome, без скачивания браузера
```

Каждый e2e-тест получает свой экземпляр фейкового API, пользователь в нём
уже вошёл администратором (другая роль — `test.use({ role: "viewer" })`).
Сценарии — те, на которых интерфейс уже ломался или которые легко сломать:
вход и выход, истёкшая сессия, что видит читатель и редактор, управление
пользователями,
проверка цели с подразделением (правило «только в», утверждённое исключение,
кандидат), матрица (состояния ячеек, утверждение кандидата, «не действует»),
панель правила (область действия, исключения, примеры, описание атрибута),
мастер правила целиком и его проверки шагов, приказы на данных без
бизнес-ключей, редактор произвольных свойств, уникальность ключей, перенос
и удаление пункта, экранирование ввода, меню действий, справочники,
переходы из замечаний, автопочинка идентификаторов, недоступный API.
