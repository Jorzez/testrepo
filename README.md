# Goal Checker Agent

Проверка формулировки цели на соответствие действующим приказам.
Требования хранятся графом в Neo4j, языковая модель (vLLM) определяет,
какие проверяемые атрибуты присутствуют в тексте цели, Cypher-запросы
находят сработавшие запреты и невыполненные требования.

```
web (nginx :3000) ──► api :8080           редактор каталога и проверка целей
api (FastAPI :8080) ─┬─► Neo4j :7687      каталог, поиск нарушений
                     └─► vLLM :8000       извлечение атрибутов из цели
seeder (разовый)   ──► Neo4j              схема + миграции из neo4j/init/
export_graph.py    ◄── Neo4j              выгрузка графа обратно в seed.cypher
```

## Быстрый старт

Настройки берутся из `.env`. Для тестового стенда он уже лежит в репозитории
со всеми переменными, поэтому стек поднимается сразу после `git pull`.
Для боевого сервера задайте свои значения по шаблону `.env.example`.
Секреты (`HF_TOKEN` — нужен только для закрытых моделей) в git не кладите:
они живут в `.env.local`, который читает `prepare.sh`.

**Машина с интернетом** (разработка, стенд) — образы и веса модели
скачаются сами:

```bash
docker compose -f docker-compose.yml -f docker-compose.online.yml up -d --build
```

**Сервер без интернета** — набор готовится на машине с интернетом
и переносится на сервер:

```bash
scripts/offline/prepare.sh              # на машине с интернетом → dist/offline/
./install.sh /opt/goal-checker          # на сервере, из перенесённого dist/offline/
```

Подробности, порядок подъёма и все переменные окружения —
в [docs/deployment.md](docs/deployment.md).

| Сервис | Адрес |
|---|---|
| Редактор каталога | http://localhost:3000 |
| API | http://localhost:8080 |
| Swagger | http://localhost:8080/docs |
| Neo4j Browser | http://localhost:7474 |

### Первая проверка

```bash
curl -s localhost:8080/ready | python3 -m json.tool

curl -s localhost:8080/check-goal \
  -H 'Content-Type: application/json' \
  -d '{"goal": "Снизить долю просроченных заявок до 5% к 31.12.2025"}'
```

> **Каталог на новой базе пуст.** В `neo4j/init/seed.cypher` сейчас только
> схема, поэтому после первого запуска `/ready` отдаёт 503. Заполнить базу:
> `reset_and_load.cypher` или редактор каталога, затем зафиксировать
> состояние выгрузкой `export_graph.py` — см. [docs/data.md](docs/data.md).

## Структура проекта

```
api/                        сервис проверки (FastAPI)
  main.py, routes.py          приложение, эндпоинты проверки и каталога
  agent.py                    извлечение атрибутов моделью, сборка результата
  graph.py                    Cypher-запросы проверки и диагностики /ready
  catalog.py, schemas.py      CRUD каталога для редактора
  diagnostics.py              развёрнутая диагностика каталога
  naming.py                   нормализация имён атрибутов
  seed.py                     загрузка .cypher-скриптов в Neo4j (сервис seeder)
  export_graph.py             выгрузка графа в seed.cypher
  verify_cypher.py            статическая проверка Cypher-запросов
  tests/                      тесты, без Neo4j и vLLM
  vendor/wheels/              колёса зависимостей для сборки без интернета
web/                        редактор каталога (React + TypeScript, Vite)
  src/api/                    клиент API и типы ответов
  src/state/                  общее состояние: данные каталога, раскрытые узлы
  src/features/               вкладки и действия над узлами
  src/ui/                     уведомления, диалоги, меню
  mock/backend.ts             фейковый API для разработки и тестов
  tests/                      e2e-тесты (Playwright)
  Dockerfile                  сборка статики в образ nginx
neo4j/init/
  seed.cypher                 схема и выгрузка данных — то, что поднимается при старте
  reset_and_load.cypher       полный сброс и заведение каталога заново
  migrations/                 разовые правки существующей базы
scripts/offline/            prepare.sh и install.sh для развёртывания без интернета
docs/                       документация
docker-compose.yml          стек для сервера без интернета
docker-compose.online.yml   надстройка для машины с интернетом
.env.example                шаблон настроек
```

## Известные ограничения

- `/check-goal` и все эндпоинты `/catalog/*` не аутентифицированы и не
  ограничены по частоте. Редактор каталога доступен любому, кто открыл
  страницу, — до выхода за пределы доверенной сети нужна авторизация.
- Текст цели попадает в промпт без экранирования — возможна prompt injection.
- Агент засчитывает атрибут по нормализованному имени, но это лечение
  симптома: двойники в графе всё равно нужно сводить, иначе часть правил
  останется на «мёртвом» узле.
- Версии Python-зависимостей зафиксированы вручную; для полной
  воспроизводимости стоит перейти на lock-файл (`pip-compile`, `uv lock`).
