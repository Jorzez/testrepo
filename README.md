# Goal Checker Agent

Проверка формулировки цели на соответствие действующим приказам.
Требования хранятся графом в Neo4j, языковая модель (vLLM) определяет,
какие проверяемые атрибуты присутствуют в тексте цели, Cypher-запросы
находят сработавшие запреты и невыполненные требования.

```
web (nginx :3000) ──► api :8080           редактор каталога и проверка целей; /api проксирует nginx
api (FastAPI :8080) ─┬─► Neo4j :7687      каталог, поиск нарушений, реестр пользователей
                     ├─► vLLM :8000       извлечение атрибутов из цели
                     └─► Keycloak        проверка токена входа (ключи realm-а)
web (браузер) ─────► Keycloak            вход пользователя (OpenID Connect, PKCE)
seeder (разовый)   ──► Neo4j              схема, данные (в пустой каталог) и миграции из neo4j/init/; до старта api
export_graph.py    ◄── Neo4j              выгрузка каталога в neo4j/init/data.cypher
```

## Быстрый старт

Настройки берутся из `.env`. Для тестового стенда он уже лежит в репозитории
со всеми переменными, поэтому стек поднимается сразу после `git pull`.
Для боевого сервера задайте свои значения по шаблону `.env.example`.
Секреты (`HF_TOKEN` — нужен только для закрытых моделей) в git не кладите:
они живут в `.env.local`.

**Сервер** — релиз из git-клона. Интернет нужен только на время релиза:
скачать образы, собрать API и интерфейс, докачать веса модели. Стек затем
работает без сети. Команды — в [docs/release.md](docs/release.md):

```bash
PULL_POLICY=always docker compose pull --ignore-buildable   # образы
docker compose build --pull                                 # API и интерфейс
PULL_POLICY=always docker compose run --rm model            # веса модели
docker compose up -d --no-build                             # запуск без сети
```

**Разработка** — стек ходит в интернет и во время работы (образы и веса
модели скачаются сами):

```bash
docker compose -f docker-compose.yml -f docker-compose.online.yml up -d --build
```

Модель на другом сервере (без GPU) — `VLLM_URL` и `VLLM_REPLICAS=0` в `.env`.
Подробности, порядок подъёма и все переменные окружения —
в [docs/deployment.md](docs/deployment.md).

| Сервис | Адрес | Откуда доступен |
|---|---|---|
| Редактор каталога | http://localhost:3000 | на адресе `WEB_BIND`, перед ним — прокси с TLS; нужен вход |
| API | http://localhost:8080 | только с самого сервера; пользователям — через `/api` интерфейса |
| Swagger | http://localhost:8080/docs | только с сервера и при `ENABLE_DOCS=1` |
| Neo4j Browser | http://localhost:7474 | только с сервера (SSH-туннель) |

Интерфейс и API требуют входа через Keycloak (OpenID Connect); роли
(читатель, редактор, администратор) назначаются в самом интерфейсе.
На стенде Keycloak поднимается из compose (профиль `idp`, адрес
http://localhost:8180, только с самой машины) с учёткой стенда, записанной в `.env`. Как
подключить корпоративный Keycloak на сервере и что именно защищено —
в [docs/security.md](docs/security.md).

### Первая проверка

```bash
curl -s localhost:8080/ready | python3 -m json.tool
```

Затем откройте http://localhost:3000, войдите и проверьте цель на главном
экране. В запросе проверки `department_id` — идентификатор подразделения
из графа: правила могут действовать только в отдельных подразделениях.
`is_student` — ставит ли цель студент: часть пунктов действует только для
студентов. Без любого из этих полей применяются все правила.

> **Каталог на новой базе пуст**, пока в `neo4j/init/data.cypher` нет
> выгрузки: `seed.cypher` — только схема, поэтому после первого запуска
> `/ready` отдаёт 503. Заполнить базу: `reset_and_load.cypher` или редактор
> каталога, затем зафиксировать состояние выгрузкой `export_graph.py` в
> `data.cypher` — см. [docs/data.md](docs/data.md). `/ready` также ждёт,
> пока vLLM загрузит модель.

## Структура проекта

```
api/                        сервис проверки (FastAPI)
  main.py, routes.py          приложение, эндпоинты проверки и каталога
  auth.py, users.py, audit.py проверка токенов Keycloak и роли, реестр пользователей, журнал аудита
  agent.py                    извлечение атрибутов моделью, сборка результата
  settings.py, apikeys.py     настройки из интерфейса и ключи доступа внешних систем
  metrics.py, history.py      очередь к модели, кэши, версия каталога; история проверок
  monitoring.py               мониторинг для администратора
  advisor.py                  советчик: как поправить описание атрибута и примеры под ожидаемый ответ
  graph.py                    Cypher-запросы проверки и диагностики /ready
  catalog.py, schemas.py      CRUD каталога для редактора
  diagnostics.py              развёрнутая диагностика каталога
  naming.py                   нормализация имён атрибутов
  seed.py                     загрузка .cypher-скриптов в Neo4j (сервис seeder)
  export_graph.py             выгрузка каталога в data.cypher
  verify_cypher.py            статическая проверка Cypher-запросов
  tests/                      тесты, без Neo4j и vLLM
web/                        редактор каталога (React + TypeScript, Vite)
  src/api/                    клиент API и типы ответов
  src/state/                  общее состояние: кто вошёл, данные каталога, форма и идущие проверки, черновики форм
  src/features/               разделы: вход, проверка, матрица правил, мастер, приказы, справочники, пользователи
  src/assets/                 логотип и шрифт Montserrat (лежат локально — стек работает без интернета)
  src/ui/                     уведомления, диалоги, меню, перехват ошибок отрисовки
  mock/backend.ts             фейковый API для разработки и тестов
  tests/                      e2e-тесты (Playwright)
  Dockerfile                  сборка статики в образ nginx
  nginx.conf.template         статика, прокси /api и заголовки безопасности
neo4j/init/
  seed.cypher                 схема — применяется при каждом подъёме
  data.cypher                 данные каталога (выгрузка) — вместе с seed.cypher, только в пустой каталог или по SEED_DATA=1
  reset_and_load.cypher       полный сброс и заведение каталога заново
  migrations/                 разовые правки существующей базы
docs/                       документация
docker-compose.yml          стек (в работе без интернета)
docker-compose.online.yml   надстройка для разработки с интернетом
.env.example                шаблон настроек
```

## Известные ограничения

- Счётчики ограничения частоты проверок и память о виденных сессиях
  Keycloak живут в памяти процесса API: uvicorn должен работать одним
  процессом. Отзыв сессии в Keycloak действует при следующем обновлении
  токена, до 5 минут.
- Указания модели в тексте цели (prompt injection) отсекаются не полностью:
  цель отделена от инструкций и подозрительные цели не разрешаются
  автоматически, но изобретательную вставку это не остановит —
  см. [доступ и безопасность](docs/security.md#указания-модели-в-тексте-цели).
- Агент засчитывает атрибут по нормализованному имени, но это лечение
  симптома: двойники в графе всё равно нужно сводить, иначе часть правил
  останется на «мёртвом» узле.
- Образы Neo4j, vLLM и Keycloak в compose закреплены тегом, а не digest:
  при релизе по тому же тегу может скачаться другая сборка образа.
